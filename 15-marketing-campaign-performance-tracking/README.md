# Day 15 — Marketing Campaign Performance Tracking

## Project Overview

This project analyzes marketing campaign performance using PostgreSQL.

The goal is to understand how businesses connect campaign spend, impressions, clicks, leads, customers, conversions, sales, revenue, ROI, and ROAS.

This is an intermediate SQL project because it focuses on business metrics, not only basic joins.

The project teaches:

- campaign performance tracking
- channel performance analysis
- marketing funnel analysis
- paid revenue logic
- click-through rate
- cost per click
- cost per lead
- customer acquisition cost
- return on ad spend
- campaign ROI
- dashboard-style marketing reporting

## Business Problem

A business runs marketing campaigns across different channels.

It does not only need to know how many impressions or clicks it received.

Useful business questions include:

- Which campaigns generated the most leads?
- Which campaigns generated real customers?
- Which channels produced the best ROI?
- Which campaigns had high clicks but low conversions?
- What is the cost per lead?
- What is customer acquisition cost?
- Which campaigns should receive more budget?
- Which campaigns should be improved or stopped?

SQL helps connect ad activity with real business outcomes.

## Database Tables

### marketing_channels

Stores marketing channels such as Facebook, Google Search, TikTok, Organic Blog, Email, Referral, Event, and Partner.

Channel type can be:

- `paid_social`
- `paid_search`
- `organic`
- `email`
- `referral`
- `event`
- `partner`

### campaigns

Stores campaign setup information such as campaign name, goal, status, budget, start date, and end date.

Campaign status can be:

- `active`
- `paused`
- `completed`
- `cancelled`

### ad_performance

Stores daily ad metrics:

- impressions
- clicks
- spend

This table is useful for CTR, CPC, and spend trend analysis.

### leads

Stores leads generated by campaigns.

Lead status can be:

- `new`
- `contacted`
- `qualified`
- `converted`
- `disqualified`

### customers

Stores customers created from converted leads.

This table connects marketing activity to customer acquisition.

### conversions

Stores conversion events such as signup, purchase, demo booked, subscription, or consultation.

### sales

Stores campaign-attributed sales records.

Payment status can be:

- `paid`
- `unpaid`
- `refunded`
- `failed`

Only `paid` sales count as revenue.

## Entity Relationship Explanation

The main relationships are:

- One marketing channel can have many campaigns.
- One campaign can have many daily ad performance rows.
- One campaign can generate many leads.
- One lead can become one customer.
- One campaign can have many conversion events.
- One campaign can generate many sales.

Foreign keys protect these relationships.

For example:

- `campaigns.channel_id` must match a real channel.
- `ad_performance.campaign_id` must match a real campaign.
- `leads.campaign_id` must match a real campaign.
- `customers.lead_id` must match a real lead.
- `sales.campaign_id` must match a real campaign.

## Marketing Funnel Explanation

The simplified marketing funnel in this project is:

1. campaign impression
2. click
3. lead
4. qualified lead
5. customer
6. paid sale

Not every click becomes a lead.

Not every lead becomes a customer.

Not every sale is real revenue.

This is why marketing analytics must connect multiple tables.

## Spend and Revenue Logic Explanation

Spend comes from the `ad_performance` table.

Revenue comes from the `sales` table, but only when:

```sql
payment_status = 'paid'
```

Unpaid, refunded, and failed sales are not counted as real revenue.

This is important because marketing ROI should be based on collected revenue, not every attempted sale.

## Conversion Logic Explanation

This project uses simple beginner-friendly formulas:

```sql
CTR = clicks / impressions
CPC = spend / clicks
Cost per lead = spend / leads
CAC = spend / acquired customers
Lead conversion rate = qualified leads / total leads
Customer conversion rate = acquired customers / total leads
```

In the analysis queries, qualified leads include leads with status `qualified` or `converted`. This keeps the funnel logic realistic because a converted customer has already passed the qualification step.

The queries use `NULLIF` to avoid division by zero.

## ROI and ROAS Explanation

ROAS means return on ad spend:

```sql
ROAS = paid revenue / spend
```

ROI is simplified as:

```sql
ROI = (paid revenue - spend) / spend
```

Both metrics use paid revenue only.

This helps a business understand whether marketing spend is producing actual value.

## Key Lessons

Marketing analytics is not only about impressions and clicks.

A campaign can have many clicks but still fail to generate customers or revenue.

Good marketing analysis connects:

- spend
- traffic
- leads
- customers
- paid revenue
- ROI

This helps a business decide where to invest, where to optimize, and where to stop wasting budget.

## How to Run This Project

Run the files in this order using PostgreSQL:

```sql
\i schema.sql
\i insert_data.sql
\i analysis_queries.sql
```

If you are using pgAdmin:

1. Open `schema.sql` and run it.
2. Open `insert_data.sql` and run it.
3. Open `analysis_queries.sql` and run each query one by one.
