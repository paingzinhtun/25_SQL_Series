# Business Questions - Product Recommendation Logic with SQL

This file connects each recommendation question with why it matters and the SQL concept practiced.

| Business / Recommendation Question | Why It Matters | SQL Concept |
|---|---|---|
| Who are all customers? | Defines the audience for product recommendations. | `SELECT`, `ORDER BY` |
| What products exist by category and brand? | Helps understand the product catalog used for recommendations. | Filtering and sorting |
| What did customers actually purchase? | Completed paid purchases are the strongest behavior signal. | Multi-table `JOIN`, `WHERE` |
| Which products did customers view? | Views show interest even when no purchase happened. | `JOIN` |
| Which products did customers wishlist? | Wishlists show stronger intent than simple views. | `JOIN` |
| What quantity was sold by product? | Identifies popular products for recommendation. | `SUM`, `GROUP BY` |
| What revenue was generated by product? | Finds products that drive business value. | Calculated revenue |
| Which products are most popular by quantity? | Supports simple popular-product recommendations. | `ORDER BY`, `LIMIT` |
| Which products generate the most revenue? | Supports revenue-aware merchandising decisions. | Aggregation |
| Which products are most popular in each category? | Helps recommend popular products inside a category. | `RANK`, window function |
| What has each customer already purchased? | Prevents recommending products already bought. | `DISTINCT`, purchase history |
| What category does each customer prefer by quantity? | Finds customer preference using purchase count. | `ROW_NUMBER` |
| What category does each customer prefer by spending? | Finds customer preference using monetary behavior. | Window ranking |
| Which viewed products were not purchased? | Creates retargeting-style recommendations. | `LEFT JOIN`, anti-join |
| Which wishlisted products were not purchased? | Creates high-intent recommendation opportunities. | `LEFT JOIN` |
| Which products are bought together? | Supports cross-sell recommendations. | Self-join |
| Which bought-together pairs rank highest? | Prioritizes strongest product pair patterns. | `RANK` |
| What can be recommended from bought-together logic? | Suggests Product B to customers who bought Product A. | CTE, anti-join |
| What popular products has a customer not purchased? | Provides a simple fallback recommendation strategy. | `CROSS JOIN`, anti-join |
| What products fit a customer's preferred category? | Personalizes recommendations based on category preference. | CTE, `ROW_NUMBER` |
| What wishlist items should be recommended? | Converts wishlist interest into recommendation action. | CTE |
| What viewed products should be recommended? | Uses browsing interest as a weaker signal. | Aggregation |
| Which customers are similar by purchased categories? | Introduces simple similar-customer logic. | Self-join |
| What products did similar customers buy? | Creates collaborative-filtering style recommendations using SQL. | CTE, anti-join |
| How can recommendation reasons be scored? | Makes recommendation priority explainable. | `CASE WHEN` |
| How can recommendations be ranked per customer? | Helps choose which recommendations to show first. | `ROW_NUMBER` |
| What are the top 3 recommendations per customer? | Produces a practical output for a campaign or app. | Window function filtering |
| Which customers have views but no purchases? | Finds customers who need popular or interest-based recommendations. | `LEFT JOIN` |
| What should non-purchasing viewers receive? | Gives new or browsing-only customers a fallback recommendation. | CTE |
| Which recommendation reasons appear most often? | Helps evaluate recommendation mix. | `GROUP BY` |
| What should a recommendation dashboard show? | Combines customer, product, score, reason, and rank. | Dashboard query |
| What would an AI-ready feature table include? | Shows how SQL prepares customer-product features for future models. | Feature engineering with SQL |
